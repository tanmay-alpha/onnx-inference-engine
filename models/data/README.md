# Data Directory

This directory manages all data used for training, evaluation, and testing of ML models.

## Structure

```
data/
├── raw/          # Original, immutable datasets
│                   - Downloaded from Kaggle, UCI, or generated
│                   - Never modified in place
│                   - Checksums stored in raw_checksums.json
│
├── processed/    # Cleaned, split, and scaled data ready for training
│                   - Generated by feature engineering pipelines
│                   - Split into train/validation/test
│                   - Scaled using StandardScaler fitted on training data only
│
└── external/     # Third-party datasets and references
                    - Supplementary data sources
                    - Public benchmark datasets
```

## Data Flow

```
external/  →  raw/  →  processed/  →  model training
              │          │
              │          └─── train.csv, val.csv, test.csv
              │
              └──── raw source files (never modified)
```

## Guidelines

1. **Never modify raw data**: Always create processed copies.
2. **Record provenance**: Log the source URL, download date, and checksum for all raw data.
3. **Reproducibility**: Save the feature pipeline (scalers, encoders) alongside processed data.
4. **Sensitive data**: Never commit PII or real transaction data to version control.

## Kaggle CreditCard Dataset

The fraud detection model can be trained on the Kaggle CreditCard Fraud Detection dataset:

```bash
# Download from Kaggle (requires kaggle CLI)
kaggle datasets download -d mlg-ulb/creditcardfraud -p data/raw/

# Unzip
unzip data/raw/creditcardfraud.zip -d data/raw/
```

The dataset contains:
- 284,807 transactions
- 30 features (V1-V28, Amount, Time)
- 492 fraud cases (0.172% of total)
- Highly imbalanced — use SMOTE or class weights

## Synthetic Data

For development and testing, the training scripts generate synthetic PaySim-style data that mimics the Kaggle dataset schema. This avoids the need for the real dataset during development.

## Data Versioning

Each processed dataset should include a `metadata.json` file:

```json
{
  "version": "1.0",
  "created_at": "2026-07-24T10:00:00Z",
  "source": "synthetic-paysim-v2",
  "n_samples": 50000,
  "n_features": 30,
  "feature_names": ["V1", ..., "V28", "Amount", "Time"],
  "n_fraud": 650,
  "split": {
    "train": 40000,
    "test": 10000
  },
  "preprocessing": {
    "scaler": "StandardScaler",
    "scaler_params": "feature_pipeline.json"
  }
}
```
